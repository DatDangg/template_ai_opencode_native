## Overview

This template provides a **multi-agent workflow** for building React Native mobile applications. Instead of manually managing tasks and phases, specialized AI agents collaborate to take your project from brief to App Store / Play Store.

**Key features:**
- 📂 **Doc-aware workflow** — drop any project docs into `docs/`, agents auto-detect and skip redundant questions
- 🤖 **Model-agnostic** — works with any AI tool (Cursor, Opencode, Windsurf, GitHub Copilot)
- 🔄 **Resumable** — pause and resume anytime, progress is saved in `.context/`
- 🧠 **Error memory** — agents learn from mistakes, avoid repeating them
- 🔍 **Independent review** — separate model reviews code to eliminate bias
- 📱 **Expo-first** — built on Expo + Expo Go, EAS Build for production
- 🗜️ **Auto context compaction** — context compressed every 3 tasks and after each layer

---

## Architecture

This template combines **4 architectural patterns**:

| Pattern | Role |
|---------|------|
| **Event-Driven** | Classify intent, route to correct agent |
| **Graph** | Dependency-driven layer breakdown (Layer 0 → 1 → 2 → ...) |
| **Loop (ReAct)** | Execute tasks, test, fix, retry until passing |
| **Blackboard** | Shared state in `.context/` — enables pause/resume |

## 🔒 Security Integration

The template ships with built-in security rules (read and applied mandatorily by multiple agents) to ensure the generated code meets security standards.

### Skills (`skills/security/`)

| Skill | Purpose |
|-------|---------|
| `semgrep-scan.md` | Static analysis security scan before commit |
| `api-owasp.md` | OWASP API Top 10 checklist for every endpoint |
| `mobile-auth.md` | Token storage (`expo-secure-store`) + mobile auth hardening |
| `sharp-edges.md` | Secure defaults & footgun config/secret/storage |
| `supply-chain-audit.md` | `npm audit` + dependency takeover risk |

### 3 Mandatory Checkpoints

1. **When coding** (`loop.md`) → read the security skill before writing any file that handles auth/storage/input/API
2. **When reviewing** (`reviewer` subagent) → run semgrep + `npm audit` + mobile security checklist before PASS
3. **When pushing** (`devops.md`/CI) → `npm audit --audit-level=high` + semgrep scan in CI

> 🔴 ERROR-severity security finding or high/critical CVE → **DO NOT PASS / do not merge**.

## 📊 Monitoring Integration

The template ships with built-in production monitoring (release health + runtime observability) based on **OpenTelemetry** — vendor-neutral, plus crash/performance tracking for mobile.

### Skills (`skills/monitoring/`)

| Skill | Purpose |
|-------|---------|
| `otel-instrumentation.md` | OTel traces/metrics/logs for React Native (network, screens) |
| `mobile-crash-performance.md` | Crash reporting + JS/native errors + performance |
| `otel-collector.md` | Collector config (receivers/processors/exporters) |
| `otel-semantic-conventions.md` | OTel naming compliance (span/attribute) |
| `production-monitoring.md` | Release health, alerting, secure logs, offline batch |

### Keys setup in Phase 0.5

Monitor keys/tokens (OTLP endpoint, service name, Sentry DSN) are asked and saved into `.env.local` in **Phase 0.5** — see `.agent/brainstorm.md` → `3.5 Monitor setup`.

### 3 Mandatory Checkpoints

1. **When coding** (`loop.md`) → read the monitoring skill before writing API/network/performance/logging files
2. **When reviewing** (`reviewer` subagent) → check crash capture, no PII in telemetry, OTel naming before PASS
3. **When pushing** (`devops.md`) → verify OTel init + env keys in Health Check

## ⚙️ Workflow Skills Integration

The template ships with 2 curated workflow skills (curated from well-known open-source repos — picking the essence, not copying verbatim) to raise code quality throughout the pipeline. These are stack-agnostic methodologies, applicable to React Native.

### Skills (`skills/`)

| Skill | Source | When used / Purpose |
|-------|-------|---------------------|
| `superpowers/` | obra/superpowers (270k⭐) | Every coding task — **Iron Law debug** (no fix without root cause) + **TDD test-first** |
| `ponytail/` | DietrichGebert/ponytail (100k⭐) | Loop while implementing — **lazy senior dev ladder**, stop at the simplest solution, avoid over-engineering |
| `aislop/` | scanaislop/aislop (curated, MIT) | Reviewer reviews **code changes** — deterministic AI-slop scan (narrative comments, swallowed errors, hidden fallbacks, `as any`, duplication, dead code, todo stubs), score 0-100 ≥80 gate, `fix --safe` mechanical, offline no API key |

### 3 Mandatory Checkpoints

1. **When debugging** (`error-analyzer.md`) → Iron Law: **NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST**. Read `superpowers/systematic-debugging.md` before proposing a fix. ≥3 failed fixes = suspect the architecture, don't try fix #4
2. **When implementing** (`loop.md`) → TDD test-first (`superpowers/test-driven-development.md`) + ponytail ladder; test fails → write minimal code to pass
3. **When reviewing** (`reviewer` subagent) → confirm test-first was followed, no over-engineering (YAGNI/DRY)

> 💡 The web design skills (`ui-ux-pro-max`, `impeccable`) **do not apply** to React Native — mobile design uses design tokens from Phase 2.5 Design Agent.

## How It Works

### Two Ways to Start

#### Option A — You have project docs already
Drop your docs into `docs/` folder (any filename, any format):
```
docs/
  PRD_v2.md          ← agent detects: business requirements
  figma-export.md    ← agent detects: design spec
  swagger.yaml       ← agent detects: API spec
  db-schema.sql      ← agent detects: ERD
```
Agent scans, classifies by content, confirms with you, then **only asks about gaps**.

#### Option B — You have an idea only
Just tell the agent what you want to build. Agent runs full interactive brainstorm.

---

### Full Pipeline

```
docs/ scan (if exists)
    │
    ▼
Brainstorm Agent
├─ Classify existing docs by content
├─ Confirm classification with user
├─ Ask ONLY about gaps not covered by docs
├─ Git setup + model selection
└─ Save .context/brainstorm-log.md
    │
    ▼
Spec Validator (different model)
├─ Cross-check SPEC vs all docs in docs/
├─ Detect conflicts between docs
├─ FAIL → Brainstorm fills gaps
└─ PASS → continue
    │
    ▼
Design Agent
├─ Analyze design reference (image/Figma)
├─ Generate design tokens
└─ Screen layout specs
    │
    ▼
Graph Agent → Break into dependency layers
    │
    ▼
┌──────── For each Layer N ────────┐
│                                   │
│  Loop Agent:                      │
│  ├─ Execute tasks                 │
│  ├─ Test FAIL → Error Analyzer    │
│  │    → fix → retry               │
│  └─ Test PASS → git commit        │
│       (rollback point)            │
│                                   │
│  Review Agent (different model):  │
│  ├─ FAIL → fix + log error memory │
│  └─ PASS → DoD checklist ✅       │
│                                   │
└──────────────────────────────────┘
    │
    ▼
👀 Human Checkpoint
"Layer N done — proceed to next layer?"
    │
    ▼
DevOps Agent
├─ Run lint + typecheck + unit tests
├─ EAS Build preview (optional)
├─ Human approves → EAS Store submit
└─ Health check
    │
    ▼
Done ✅ → Extract patterns → Update common-errors.md
```

## Agent Roles

| Agent | File | Description |
|-------|------|-------------|
| **Brainstorm** | `.agent/brainstorm.md` | Doc-aware requirements gathering — scans docs/, classifies by content, only asks about gaps |
| **Spec Validator** | `.opencode/agent/spec-validator.md` (subagent) | Cross-validates spec against all available docs; detects conflicts |
| **Design** | `.agent/design.md` | Creates design system, analyzes reference images, generates design tokens |
| **Graph Planner** | `.agent/graph.md` | Decomposes project into dependency-ordered layers |
| **Loop** | `.agent/loop.md` | Orchestrates tasks (ReAct); code gọi subagent `builder` |
| **Builder** | `.opencode/agent/builder.md` (subagent) | Implement code + test cho 1 task |
| **Builder (strong)** | `.opencode/agent/builder-strong.md` (subagent) | Task khó — opt-in, chỉ khi user yêu cầu rõ |
| **Reviewer** | `.opencode/agent/reviewer.md` (subagent) | Independent code review (different model family) |
| **Bug Check Scanner** | `.opencode/agent/bug-check-scanner.md` (subagent) | Read-only scanner cho `/bug-check` — chỉ ghi `scan.md` |
| **Error Analyzer** | `.agent/error-analyzer.md` | Root cause analysis; builds error memory to prevent recurrence |
| **Context Manager** | `.agent/context-manager.md` | Summarizes and pins context to prevent amnesia in long sessions |
| **Rollback** | `.agent/rollback.md` | Git commit strategy; reverts layer on failure |
| **DevOps** | `.agent/devops.md` | Git init, EAS Build, store submission |
| **Workflow** | `.agent/FEATURE_WORKFLOW.md` | Nguồn luật duy nhất cho bug / feature / update (maintenance) |

## Maintenance Workflow

Sau khi project đã tồn tại (đã build xong), dùng workflow maintenance — luật đầy đủ ở
`.agent/FEATURE_WORKFLOW.md` (single source). Router: `AGENTS.md`. Giá trị project: `.agent/PROJECT_PROFILE.md`.

| Command | Dùng khi | Tính chất |
|---|---|---|
| `/setup-profile` | Onboarding / đổi cấu hình (branch, verify commands, model, DB) | Ghi `PROJECT_PROFILE.md` + sync model/permissions |
| `/bug` | Một bug đã biết, hoặc list bug đã xác nhận | Diagnose → task → builder → reviewer → progress → commit-first |
| `/bug-check` | Khu vực/màn mơ hồ, "cảm giác nhiều lỗi" | **READ-ONLY** — liệt kê defect vào `tasks/bug-<slug>/scan.md`, dừng chờ user chọn |
| `/feature` | Thêm/sửa/bỏ tính năng | Classify ADDITIVE/MODIFY/REMOVE → spec delta → phase/task → builder/reviewer/spec-validator |

- Model mạnh `builder-strong` bị gate cứng: `opencode.jsonc` → `permission.task."builder-strong": "ask"`.
- Commit sau PASS review (commit-first); push chỉ khi user yêu cầu rõ hoặc `auto_commit_after_pass: true`.
- Trước commit chạy `pnpm check:workflow` (hoặc `node scripts/check-workflow-consistency.mjs`).
- Sau khi sửa `.opencode/` hoặc `opencode.jsonc` → **restart opencode** (config không hot-reload).

## Getting Started

### Option A — With existing docs

```bash
# 1. Clone the template
git clone https://github.com/DatDangg/template_ai_opencode_native.git my-app
cd my-app

# 2. Drop your docs into docs/
cp ~/my-project-docs/* docs/

# 3. (Optional) Edit docs/INDEX.md to hint what each file is

# 4. Install dependencies
npm install   # or: npx expo install

# 5. Open with your AI tool
opencode

# 6. Start
# "Read AGENT.md and start the project"
# Phase 0.5 sẽ chạy /setup-profile để điền PROJECT_PROFILE + chọn model → restart opencode
```

```bash
# 1. Clone the template
git clone https://github.com/DatDangg/template_ai_opencode_native.git my-app
cd my-app

# 2. Install dependencies
npm install

# 3. Open with your AI tool

# "Read AGENT.md and start the project"
```

```
Read AGENT.md and resume the project
```

Agent reads `.context/progress.json` and continues from the last checkpoint.

## docs/ Folder

The `docs/` folder is where you drop any existing project documentation. The agent automatically classifies each file by content — no need to follow a naming convention.

### Supported Doc Types

| Type | Detected by | Template file |
|------|-------------|---------------|
| Business Requirements (BRD/PRD) | "user story", "acceptance criteria", "business rule" | `docs/BRD.md` |
| Design Spec | screen names, colors, layout, component names | `docs/DESIGN.md` |
| API Spec | endpoints, request/response schemas, HTTP methods | `docs/API_SPEC.md` |
| Database Schema (ERD) | table definitions, relationships, indexes | `docs/ERD.md` |

### docs/INDEX.md (optional)

If you want to skip auto-detection, create `docs/INDEX.md`:

```markdown
- PRD_v2.md: business requirements
- figma-export.md: design reference
- swagger.yaml: api spec
```

## Agent Models

Model khai ở `.agent/PROJECT_PROFILE.md` → block `models:` (**KHÔNG** dùng `.env.local`).
Chọn/đổi bằng `/setup-profile` (liệt kê model khả dụng thật qua `scripts/resolve-model.mjs`),
hoặc sửa tay rồi `node scripts/apply-agent-models.mjs --write` để sync `model:` frontmatter vào `.opencode/agent/*.md`.
Sau đó **restart opencode** (config không hot-reload).

| Agent | File | Ghi chú |
|-------|------|---------|
| Builder | `.opencode/agent/builder.md` | Model chính viết code |
| Builder (strong) | `.opencode/agent/builder-strong.md` | Opt-in — chỉ khi user yêu cầu rõ |
| Reviewer | `.opencode/agent/reviewer.md` | Nên khác **model family** với builder |
| Spec Validator | `.opencode/agent/spec-validator.md` | Family thứ 3 nếu có |

## Git & CI/CD

### Branch Strategy

Default **staging-direct** (giá trị thật ở `.agent/PROJECT_PROFILE.md`):

```
<target_branch>   ← làm việc + commit + push trực tiếp (vd staging)
main              ← production (forbidden_branch: cấm push trực tiếp; chỉ promote sau UAT + user duyệt)
feature/<slug>    ← chỉ khi user yêu cầu feature branch; push current branch, PR chỉ khi user yêu cầu
```

Gate cứng ở `opencode.jsonc` (`permission.bash`): chặn push `forbidden_branch`, `--force`/`-f`, và DB destructive shortcuts.

### EAS Build Profiles (`.devops/templates/`)

| Profile | Purpose |
|---------|---------|
| **Preview** | Internal distribution via EAS (testers, QA) |
| **Production** | App Store + Play Store submission |
